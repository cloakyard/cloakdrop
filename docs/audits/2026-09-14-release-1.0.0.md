# September 14, 2026 — 1.0.0 release preparation

The source is version **1.0.0**, build **20260914**. A fresh, optimized arm64 Release app is installed at `/Applications/CloakDrop.app`, and a matching local DMG was built and verified. This is extensive local release testing, not certification of every feature, provider, operating-system failure mode, or Apple distribution requirement.

**Release readiness still has unresolved signing/notarization and bundled-runtime security limits.** Ad-hoc distribution is possible, as the installation guide explains, but this build cannot be described as notarized or as having fully current bundled dependencies. No GitHub release, tag, website deployment, or public upload was made during this work.

## Corrections and simplification

The transfer engine now rejects malformed persisted segment layouts, duplicate IDs, invalid ranges and impossible progress before resuming. Segment ID allocation handles `Int.max`, mirror indexes are normalized, and connection-bound checks avoid multiplication overflow. Duplicate media segment IDs are rejected before writing shared staging data.

Moved security-scoped destinations are resolved before reading, writing, publishing, revealing or cleaning their files. Updated paths and stale bookmarks are persisted. Category descendants remain inside the granted folder. An ambiguous replacement at the original location fails safely; there is no fallback that silently uses that replacement. Error messages describe restoring the original folder/access and retrying. Existing partial progress is retained.

The bandwidth limiter responds promptly when a limit is raised or disabled. Its unused duplicate scheduling implementation and the tests of that dead implementation were removed; real aggregate-throughput tests remain. Browser handoff is consolidated and captures its callback/referrer/user-agent before asynchronous cookie retrieval. Favicon and thumbnail callbacks reject stale/deleted results.

Startup database failure now presents Retry/Quit instead of terminating through `fatalError`. Numeric settings, segment/progress decoding, Metalink parsing and subtitle timestamps reject or safely bound malformed and extreme inputs. The capture inbox bounds JSON reads/writes, rejects symlinks and preserves directories masquerading as JSON files. Recursive unused JSON-discard code was removed, and best-format selection uses a linear scan.

Remembered origin credentials are scoped by scheme, host and effective port. Legacy host-only entries are no longer automatically reused; a user may need to enter credentials again. Proxy credentials remain separate. Share Extension presentation is guarded against duplicate invocation.

No widget, WidgetKit target or external-browser extension implementation is present. The functioning native macOS Share Extension is retained. A stale browser-extension comment was corrected; a `.crx` MIME mapping is ordinary download classification, not extension scaffolding.

## Apple API and bundle review

Twenty text fields now share a small compatibility helper using macOS 27's `.bordered` style, with `.roundedBorder` on macOS 26. The SDK availability was checked, both branches compile, and native light/dark UI was inspected during verification. The macOS 26 fallback was not run on a second OS installation. macOS 27 menu-icon defaults are retained. See [macOS 27 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes).

Liquid Glass remains on floating/navigation chrome, with ordinary scrolling rows and SF Symbols. This follows the scope described in Apple's [materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials); it is not an App Review approval.

The bundled yt-dlp executable moved to `Contents/MacOS`; its native modules and Python framework moved to `Contents/Frameworks`. Relative aliases preserve PyInstaller's data/import paths. The packaging phase is now a standalone script with bounded cleanup of its own files. No physical Mach-O code remains in Resources. All bundle aliases resolve. Helpers and nested code are signed explicitly from leaves outward; `--deep` is used for verification, not signing. This follows Apple's [nonstandard bundle guidance](https://developer.apple.com/documentation/xcode/embedding-nonstandard-code-structures-in-a-bundle) and [distribution signing guidance](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac/).

Sandbox/hardened-runtime settings remain enabled. The resolver's existing library-validation exception is retained pending a real Developer ID run; this local audit does not establish that the exception can be removed. Apple's currently documented required-reason privacy-manifest enforcement scope does not list macOS, so no fabricated reason declarations were added. GRDB's supplied privacy manifest remains bundled. See [privacy manifest files](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files).

## Outstanding release limits

1. **Developer ID/notarization:** no identity was available. Distribution signing, a successful notary submission/staple, Gatekeeper behavior on a clean Mac, and Release App Group/Share Extension handoff remain unverified. Ad-hoc integrity checks do not replace [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).
2. **Frozen resolver runtime:** the official [yt-dlp 2026.08.19 release](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.08.19) was still the latest stable release checked today. Its bundled runtime remains older than available security fixes, including OpenSSL 3.5.7 versus the [3.5.8 security release](https://mirror.openssl-library.org/news/openssl-3.5-notes/). Moving/signing it does not patch that runtime. A current upstream bundle or separately reviewed replacement is needed before claiming all bundled components are current. See the [vendor guide](../../apps/macos/Vendor/yt-dlp/README.md) and previous dependency audits.
3. **Coverage:** macOS 26 runtime behavior, physical power-loss durability, live authenticated FTP/FTPS/proxy services, every video provider, login-item registration, scheduled wake/power actions, full accessibility assistive-technology use and notarized extension delivery were not all tested interactively. Appropriate core tests passed, but they cannot certify those environments.
4. **Publishing:** website beta wording still describes the published binary. Update the site and release notes together with the actual public 1.0.0 upload, after addressing the release limits above. This audit is not an App Store approval or a zero-bug guarantee.
