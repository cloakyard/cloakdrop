# Video and media audit — 2026-09-06

The existing design is a good foundation: the browser observes existing traffic, yt-dlp resolves page metadata, and CloakDrop's own engine transfers and assembles the selected media. This audit fixed concrete failures in that handoff. It does not certify every extractor/site, live recording, or protected content.

## Implemented fixes

| Finding | Result after the change | Regression evidence |
| --- | --- | --- |
| Redirected manifests resolved relative child URLs against the original endpoint. | Master playlists, variant playlists, audio and subtitle playlists now resolve against the final response URL. Manifest buffering checks its limit before appending a chunk and observes cancellation. | Redirected master + separately redirected media playlist, including relative initialization and media segments. Existing manifest size and resolver suites pass. |
| yt-dlp's `manifest_url` was discarded. An HLS video child lost the master's audio/subtitle groups; DASH fragment entries could not reach the MPD resolver. | The extracted format preserves its parent HLS/DASH manifest. Adaptive fallback fetches the parent and retains its exact request context, quality choices and rendition groups. | Parent HLS and DASH metadata fixture. Live Vimeo returned 12 HLS formats with parent manifests, demonstrating this exact input shape. |
| Failed separate audio resolution was silently converted into successful preparation of a silent video; the app also treated page-derived DASH manifests like progressive direct files. | Required audio resolution now throws. Default audio selection is centralized so resolved DASH manifests keep separate audio while direct progressive tiers keep their own sound. A higher silent direct tier cannot displace a complete lower tier. | Missing audio playlist, complete-vs-silent tier, and parsed DASH video+audio with a progressive control regression. |
| A live GUI check of Apple's bipbop master exposed a URI-less default Audio1 hiding downloadable Audio2 in audio-only mode. | The model distinguishes independently fetchable audio tracks from in-band renditions. Audio-only defaults/fallbacks choose a standalone track; normal video keeps the manifest's in-band default. | Exact same-language Audio1-without-URI + Audio2-with-URI fixture; nil/stale selection fallback, preserved in-band video behavior, and no standalone offer for in-band-only masters. |

| Formats without dimensions/standard codec names could be labeled Audio despite containing video. | Optional explicit video-track presence from the extractor takes precedence over inferred codec/resolution evidence. | Collapsing multilingual audio formats by bitrate could remove the format ID referenced by a video variant. | Language groups remain stable when the selected audio container changes; the default language remains resolvable. | AAC + Opus variants in English plus Spanish alternate audio. |
| Top-level extractor HTTP headers were discarded; mixed header casing could preserve two conflicting user agents. | Top-level headers are inherited, selected-format headers replace them case-insensitively, and extractor referrers override stale browser convenience fields. | Non-HTTP/relative formats, explicit DRM formats, or extension-identified playlists could reach the direct-file path. | Direct formats require an HTTP(S) URL and exclude explicit DRM and playlist extensions. | Malformed manifest scalars could crash on empty HLS range arrays, overflowing sequence/timestamp arithmetic, giant template padding or dimensions/durations beyond safe arithmetic. | HLS rejects invalid segment/init byte ranges and sequence values. DASH checks integer addition/multiplication, bounds remote padding and validates timing. | A user's shell yt-dlp configuration or plugins could alter application behavior. | Extraction explicitly uses `--ignore-config`, `--no-plugin-dirs`, `--simulate`, `--no-cache-dir` and the argument terminator. Invalid page schemes are rejected before launching. Cancellation stays cancellation; private output handles close on errors. | Mock-runner argument tests; actual bundled CLI smoke tests with those flags. |
| “No grabbable formats” claimed protection without evidence of DRM. | The message says no supported download was found and suggests playing the video in the built-in browser. | Source review and build verification by the main audit. |

The one-primary-item media shelf policy is intentional and unchanged. A valid HLS candidate outranks a direct MP4 on the same page; this does not mean the collector missed the MP4. Closed-shadow-player verification should use an isolated page without a higher-ranked manifest candidate.

## Remaining boundaries and follow-up priorities

- **Live recording is not implemented.** HLS resolution currently takes a finite playlist snapshot; it does not refresh a sliding live window. `ExtractedMedia.isLive` is informational. Twitch/live URLs must not be advertised as complete live recording support. A complete implementation needs explicit recording controls, playlist refresh, discontinuity/window handling, duration/stop policy and relaunch semantics.
- **Per-resource request context is still shared.** A media plan applies one header set to video, audio, keys and subtitles. Sites that require different headers or scoped cookie/auth credentials per rendition/CDN may still fail. The safe next architecture step is resource-scoped request context persisted with each media resource, with origin-aware redirect handling and tests; copying page cookies broadly is not an acceptable shortcut.
- **Extractor proxy routing needs a dedicated seam.** Manifest/payload requests use the configured HTTP client. The metadata subprocess currently has no explicit parameter for the app's manual proxy setting. Validate or wire that configuration separately rather than assuming metadata uses the same route as engine downloads.
- **Expiring media URLs need re-resolution semantics.** Interrupted direct/adaptive transfers retain resolved URLs; some signed URLs can expire before a later resume. Reliable refresh must preserve media identity and selected quality/language, and must never combine bytes from changed content.
- **DRM and site restrictions remain unsupported.** Explicit DRM is rejected; access requirements, bot checks, geo restrictions, unsupported protocols and site changes can still prevent extraction. No DRM bypass, remote component download, new dependency, telemetry or background network polling was added.
- **Broader coverage still needs a maintained integration corpus.** The allowlist remains conservative for pasted URLs, while generic visited pages with observed players can use page extraction. Test more public HLS/DASH sites and authenticated browser-to-CDN handoffs before claiming universal compatibility. Automated offline fixtures should remain the deterministic regression baseline.
