# Compatible MP4 output — October 29, 2026

Verified locally on macOS 27.2 (26B123), arm64, with the ad-hoc Debug build.
This extends the [YouTube timing fix and dependency refresh](2026-10-29-youtube.md).

## Behavior

The shared quality picker offers **MP4 (compatible)** and **Original quality** for
extracted video pages. MP4 is selected by default when the source supplies H.264
video and AAC-LC audio. It filters formats before choosing quality tiers and audio
languages, then combines the selected streams without re-encoding. Higher source
qualities can remain exclusive to Original, which may produce MKV. If compatible
renditions are unavailable, MP4 is disabled and the picker explains why.

The Add Download sheet, quick paste, and built-in browser page capture use the same
page-resolution/picker path. Manual page submissions and browser captures open the
picker even when automatic quality is enabled for other streaming links. Audio-only
mode retains the source audio choices and hides the video output selector.

`MediaPlan.outputFormat` persists through restart/resume; old records retain their
previous behavior. Backends check actual downloaded codecs before compatible MP4
export. If MP4 cannot be produced, the transfer fails with staging retained, rather
than silently publishing raw bytes or MKV. Output names are reserved as MP4 before
transfer, preserving the existing no-overwrite behavior.

This is source selection and lossless repackaging during download. It does not add
a generic converter for existing local MKV files or lossy codec transcoding. No
library or helper codec dependency was added. The pinned versions and official
frozen-runtime exceptions from the preceding dependency audit remain unchanged.

## Broader timing regression found during verification

The first H.264 MP4 test still lasted 88.866667 seconds while its audio ended near
44.44 seconds. The source format 136 contains top-level `moof` fragments. FFprobe
reads its video as 44.433333 seconds at 30 fps, but Apple's AVAsset reader already
reports 88.866667 seconds before muxing. Comparing an export against AVAsset's own
duration would therefore miss this error.

The native backend now rejects fragmented MP4 inputs independently of codec. A
bounded top-level box scan skips payload bytes and handles ordinary, extended and
end-of-file box lengths. FFmpeg stream-copy then preserves the original timestamps.
Explicit MP4 output uses `-movflags +faststart`; Original retains the existing MKV
fallback. The AV1 codec guard remains in place. A tiny synthetic fragmented H.264
fixture tests this dispatch without network or copyrighted media in the repository.

The failed verification output and its record were removed. Its probe remains as
[`direct-probe.json`](evidence/2026-10-29-mp4/direct-probe.json) for diagnosis.
